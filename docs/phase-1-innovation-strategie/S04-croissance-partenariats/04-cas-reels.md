# Cas réel – Microsoft rachète GitHub : croissance externe

## Le dossier

**Les faits.** Le **4 juin 2018**, **Microsoft** annonce l'**achat de GitHub** pour **7,5 milliards de dollars, payés en actions Microsoft**. GitHub est la plus grande plateforme mondiale d'hébergement de code source : en **mars 2018**, elle compte **28 millions de développeurs** et **85 millions de dépôts** de code. Elle avait levé **350 millions de dollars** et été valorisée environ **2 milliards de dollars en 2015**.

**Après le rachat.** Un porte-parole de Microsoft indique que GitHub « **fonctionnera de manière indépendante** », comme LinkedIn après son rachat. **Nat Friedman** (ancien dirigeant de Xamarin, alors vice-président de Microsoft) devient **directeur général** de GitHub ; le fondateur, **Chris Wanstrath**, devient *technical fellow* chez Microsoft.

## Pourquoi ce cas est utile

Il illustre la **croissance externe** (acquisition) : une entreprise intègre une autre pour obtenir **rapidement** des **clients**, des **compétences** et un **accès à un marché**. Il pose les **questions du cours** : le **prix** (financement par actions), l'**intégration** (cultures) et le **maintien de l'identité** de l'entreprise rachetée.

## Questions

**1.** Calcule le **prix payé par développeur** de la plateforme, puis le **rapport** entre le prix de 2018 et la valorisation de 2015.

<details markdown="1">
<summary>Voir la réponse attendue</summary>

\(7{,}5 \times 10^9 / 28 \times 10^6 \approx 268\) dollars par développeur. Rapport : \(7{,}5 / 2 = 3{,}75\) : le prix est **3,75 fois** la valorisation de 2015 (environ trois ans plus tôt).
</details>

**2.** Pourquoi payer **en actions** plutôt qu'en argent ? Cite **un avantage** et **un risque**.

<details markdown="1">
<summary>Voir la réponse attendue</summary>

**Avantage** : l'acheteur **ne mobilise pas de trésorerie** et les vendeurs **partagent** le sort du groupe. **Risque** : le **cours** de l'action peut **varier** (la valeur réelle de l'opération change) et les **actionnaires** de l'acheteur sont **dilués**.
</details>

**3.** Microsoft dit que GitHub « fonctionnera de manière indépendante ». À quel **risque d'intégration** cela répond-il ?

<details markdown="1">
<summary>Voir la réponse attendue</summary>

Au risque de **perte de confiance** des utilisateurs (des développeurs attachés à une plateforme **neutre**, y compris pour des projets concurrents de Microsoft) et au risque de **départ des personnes clés**. Préserver l'**autonomie** limite ces risques.
</details>

**4.** Compare la croissance **externe** ici avec la croissance **interne** : pourquoi Microsoft n'a-t-elle pas simplement construit son propre GitHub ?

<details markdown="1">
<summary>Voir la réponse attendue</summary>

Construire en interne est **lent** et sans garantie d'**adoption** : l'**effet de réseau** (28 millions de développeurs, 85 millions de dépôts) est **difficile à reproduire**. Le **rachat** apporte **immédiatement** ces utilisateurs. En contrepartie, il est **coûteux** et expose aux **difficultés d'intégration**.
</details>
